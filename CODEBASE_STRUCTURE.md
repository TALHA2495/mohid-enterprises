## Business Logic & Workflow (RFQ funnel)

1. **Catalog**: product data lives entirely in `components/showroom-section.tsx` (`products: Product[]`).
2. **Detail**: selecting a product swaps to `ProductDetail` (`showroom-detail.tsx`), which builds a context URL: `/quote?product=...&material=...&width=...&moq=...` (moq parsed from the product's "Minimum order quantity" spec).
3. **Form**: `QuoteForm` (`quote-form.tsx`) reads those params → passes them to `createRfqSchema` (`lib/rfq-schema.ts`).
4. **Dynamic MOQ floor**: `parseMoq` extracts the numeric MOQ (e.g. "500 meters" → 500); a `superRefine` gate rejects quantities below it. Without product context any positive quantity passes.
5. **Submit**: after RHF + Zod validation, fields compile into a WhatsApp Click-to-Chat message → `window.open('https://wa.me/<NEXT_PUBLIC_WHATSAPP_NUMBER>?text=...')` → success state. Number from `.env.local`, fallback `92XXXXXXXXXX`.
6. **Tests**: `node --test scripts/rfq-whatsapp.test.mts` — MOQ gate, field rules, `parseMoq` edge cases, URL build/encoding parity with `onSubmit`.

## Design System (current light theme)

> Kept in sync with `DESIGN.md` — both documents describe the same tokens.

### Core Principles
1. **Light-first** — No light/dark switch; the site is always light (`#f4f7f8` base, white cards)
2. **Content is immutable** — Design changes touch class strings only; copy/data must not be rewritten
3. **Green is the only accent** — Never introduce secondary accent hues
4. **Minimal diffs** — Reuse existing utilities and patterns; don't add dependencies

### Color Tokens

| Token | Value | Usage |
|---|---|---|
| Page background | `#f4f7f8` | `<main>`, section backgrounds, footer |
| Card background | `bg-white` | Cards, panels, form card, mobile menu, showroom cards |
| Card hover | `#f0f5f4` | Showroom grid card hover |
| Primary button | `bg-[#01aa3f]`, hover `#00ff59` | CTAs, header "Request a Quote" |
| Accent | `#00c853` | Mono eyebrows, check icons, type labels, links, focus borders |
| Hero accent | `#1ada67` | Serif `<em>` highlights, hero eyebrow (unchanged) |
| Text on light surfaces | `text-black` · `text-black/85` · `/70` · `/55` · `/50` | Headings → captions |
| Text over photos | `text-white` · `text-white/80` + `drop-shadow-sm`/`-md` | Hero/eyebrow/lead text on all 5 page backdrops |
| Borders (light surfaces) | `border-black/10` cards · `/15` `/20` controls · `black/[0.07]` row dividers | All strokes |
| Borders (over-photo controls) | `border-white/40`–`/60` + `drop-shadow` | Ghost pills, filters, close buttons |
| Inputs | `bg-black/[0.03]` + `border-black/10`, focus `border-[#00c853]`, `placeholder:text-black/45` | Form fields |


### Typography

| Font | Variable | Usage |
|---|---|---|
| Inter | `--font-sans` | Default body (loaded via `next/font/google`) |
| Fraunces | `--font-fraunces` | Page titles, band headings (via `font-[family-name:var(--font-fraunces)]`) |
| Playfair Display | `--font-serif` | Available (loaded `preload: false`); legacy product-detail title |

- **Eyebrow pattern**: `font-mono text-[10px]–[11px] uppercase tracking-[0.2em] text-[#00c853]`
- **Two-tone headings**: white statement (over photo) + `<em className="text-[#1ada67] italic">green phrase</em>`

### Layout Patterns
- Container: `mx-auto max-w-7xl px-4 sm:px-6` (hero, showroom)
- Narrow containers: `max-w-2xl` (quote), `max-w-5xl` (standards)
- Hero backdrops: `h-[min(760px,100vh)]` (lg up to `100vh`/`95vh`), `<Image fill quality={70} sizes="100vw">` — **no overlays**; over-photo text relies on drop-shadow for legibility

## Conventions & Patterns

### Path Aliases
- `@/*` maps to project root (e.g., `@/components`, `@/lib/utils`)

### Utility Function
- `cn(...inputs: ClassValue[])` — merges clsx + twMerge for conditional class names

### Server vs Client Components
- **Server components** (default): `site-footer.tsx`, `hero-section.tsx`, `hero-stats.tsx`, `factory-page.tsx`, `standards-page.tsx`
- **Client components** (`'use client'`): `site-header.tsx` (mobile menu state), `showroom-section.tsx` (filters/pagination/selection), `showroom-detail.tsx` (gallery state), `certificate-gallery.tsx` (lightbox), `quote-form.tsx` (RHF submission), `analytics-loader.tsx` (dynamic import)

### Product Data Structure
Defined in `components/showroom-section.tsx`:
```typescript
type Product = {
  name: string
  type: string
  description: string
  material: string
  width: string
  colors: string
  finish: string
  image: string
  specs: [string, string][]  // tuple of [label, value]
}
```

### Image Conventions
- `next/image` `<Image>` everywhere (backdrops, cards, certificates, gallery) with explicit `quality` (55–70) and `sizes`
- Quality ladder allowed by `next.config.mjs`: `qualities: [55, 70, 75]`
- Only the certificate **lightbox** renders a native `<img>` (full-resolution, encode-safe URL)
- Icons are **generated** by `scripts/generate-icons.mjs` from `public/images/LOGO MOHID.webp` — don't hand-edit them
- `sharp`-based `scripts/optimize-images.mjs` re-encodes sources in place (git keeps originals)

### CSS Conventions
- Tailwind v4 syntax (`@import 'tailwindcss'`, `@theme inline`, `@custom-variant dark`)
- shadcn CSS variables in `globals.css` (`:root`) are light-valued but effectively unused by pages — inline arbitrary values preferred (e.g., `bg-[#f4f7f8]`, `text-[#00c853]`)
- No CSS modules or styled-components — pure utility classes

## Important Notes

1. **Quote page has a standalone layout** — no `SiteHeader`; logo + wordmark + close button over the backdrop photo
2. **Factory & Standards pages** each contain their own local `DarkShell` copy (legacy name — it's a light shell with a backdrop photo)
3. **Showroom product data** lives entirely within `components/showroom-section.tsx` (not separated)
4. **No API routes** — static marketing site; the only "backend" interaction is the WhatsApp deep link
5. **Analytics** (`@vercel/analytics` via `AnalyticsLoader`) renders only in production (`process.env.NODE_ENV === 'production'`)
6. **Scrollbar hiding** is applied globally on mobile (`max-width: 767px`) and on the product-filter row via `globals.css`
7. **Favicons/icons are generated assets** — run `scripts/generate-icons.mjs` rather than editing them; `layout.tsx` references light/dark media variants + `icon.svg`
8. **Mobile menu** is always-mounted with CSS transitions (`duration-500 ease-in-out`, opacity + translate) — mount/unmount would kill the exit animation
9. **Over-photo text rule**: text sitting directly on backdrop photos uses `text-white` + `drop-shadow`; text on light surfaces uses `text-black/*`. No white/light overlays are added over any image
